▼
createThreadThunk is a Redux Toolkit async thunk. Redux automatically dispatches a threads/createThread/pending action, then calls the async function. If it resolves, fulfilled fires; if it throws, rejected fires. On 401 errors the frontend utility clears localStorage and redirects to /login.
threadListSlice.js:30–40
export const createThreadThunk = createAsyncThunk(
  "threads/createThread",
  async (data, thunkAPI) => {
    try {
      const newThread = await createThread(data); // service call
      return newThread;
    } catch (err) {
      return thunkAPI.rejectWithValue(handleApiError(err));
    }
  }
);

const getAuthHeaders = () => {
  const token = localStorage.getItem("token");
  return token ? { Authorization: `Bearer ${token}` } : {};
};

export const createThread = async (data) => {
  const res = await axiosInstance.post(
    THREAD_API.CREATE, // "/threads"
    data,
    { headers: getAuthHeaders() }
  );
  return res.data.data; // unwrap the nested "data" key
};

Every incoming request passes through the middleware chain in order before reaching any route. Helmet sets security headers. Rate limiter rejects if the IP has exceeded 100 requests in 15 minutes. CORS allows the frontend origin. express.json() parses the JSON body into req.body.

5
authHandler verifies the JWT
src/middleware/authHandler.js
▼
The route POST /api/threads is defined as router.post("/", authHandler, createThread), so authHandler runs first. It extracts the token from the Authorization header, verifies it with jwt.verify(), then looks up the user in MongoDB to confirm they still exist. The user's _id is attached to req.user.userId for the controller to use.
src/middleware/authHandler.js
const token = req.header("Authorization")?.replace("Bearer ", "");

if (!token) throw createAppError("No token provided", 401);

const decoded = jwt.verify(token, process.env.JWT_SECRET);
const user = await User.findById(decoded.userId).select("-password");

if (!user) throw createAppError("User not found", 401);

req.user = { userId: user._id }; // passed to controller
next();                         // hand off to createThread
If token is missing or invalid: throws a 401 error → Express passes it to errorHandler → returns { success: false, message: "..." } → frontend's handleApiError() clears localStorage and redirects to /login.
6
Controller validates & delegates
src/controllers/threadController.js — createThread()
▼
The controller destructures title, content, subreddit from req.body, and takes the author ID from req.user.userId (set by authHandler). It does a presence check, then delegates to the service layer.
src/controllers/threadController.js:31–49
export const createThread = async (req, res) => {
  const { title, content, subreddit } = req.body;
  const author = req.user.userId; // injected by authHandler

  if (!title || !content || !subreddit) {
    throw createAppError("Title, content, and subreddit are required.", 400);
  }

  const populatedThread = await createNewThread(
    title, content, author, subreddit
  );

  res.status(201).json({
    success: true,
    message: "Thread created successfully",
    data: populatedThread
  });
};
7
Service saves to MongoDB
src/services/threadService.js — createNewThread()
▼
The service creates a Mongoose Thread document and calls .save(). MongoDB assigns a new _id and createdAt / updatedAt timestamps. Then the service immediately re-fetches the saved document using .populate() so the response includes the full author name and subreddit name instead of raw ObjectId references.
src/services/threadService.js:27–40
export const createNewThread = async (title, content, author, subreddit) => {
  const newThread = new Thread({ title, content, author, subreddit });
  await newThread.save(); // INSERT into MongoDB

  // Re-fetch so we return full objects, not just IDs
  const populatedThread = await Thread.findById(newThread._id)
    .populate({ path: "subreddit", select: "name description" })
    .populate({ path: "author", select: "name" });

  if (!populatedThread) throw createAppError("Failed to create", 500);

  return populatedThread;
};

⚠ Error paths
!
401 — Token invalid
authHandler.js
▼
jwt.verify() throws or user not found in DB. createAppError("Token is not valid.", 401) is thrown. Express catches it via errorHandler and sends a 401 JSON response. Frontend's handleApiError() detects the 401, clears localStorage, and redirects to /login.
!
400 — Missing fields
threadController.js
▼
Controller checks if (!title || !content || !subreddit). If any field is missing it throws a 400 error. The frontend createThreadThunk catches this via rejectWithValue, sets state.error in Redux, and the form calls alert("Failed to create thread.").
!
429 — Rate limited
app.js — express-rate-limit
▼
If the same IP sends more than 100 requests in 15 minutes, the rate limiter middleware rejects the request before it reaches any route or authentication logic. Returns HTTP 429. The frontend displays a generic error alert.
